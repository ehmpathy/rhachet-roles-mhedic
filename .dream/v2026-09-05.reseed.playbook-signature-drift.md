- **kind**  = reseed
- **owner** = `rhachet-roles-bhrowser` (repo=bhrowser, role=playwright)
- **caught** = 2026-09-05

## .the cue that fired

wrote a playbook straight from the documented shape in
`howto.browser-action-playbooks.md`, invoked it, and the skill refused it:

```
BadRequestError: playbook must export an action function
  context: {"exports":["default"], "hint":"export const action = async ({ page, browser }) => { ... }"}
```

⚠️ **the brief is the paved path, and it leads off a cliff.** every worked example in it —
seven of them — teaches a shape the runtime rejects.

## .the gap, precisely

| where | the brief teaches | `browser.action` actually demands |
|---|---|---|
| export | `export default async (...)` | `export const action = async (...)` |
| params | two positional: `(page, ctx)` | one named object: `({ page, browser })` |

evidence — the runtime check at
`rhachet-roles-bhrowser/dist/domain.roles/playwright/skills/browser.action.ts:97`
throws when `exports` lacks `action`, and its own hint states the correct shape.

the brief's `.signature shape`, `.format`, all four `.patterns` blocks, and both
`.credentials via context` blocks carry the wrong form.

⇒ the two-positional-arg form also contradicts
`rule.require.input-context-pattern` (ehmpathy/mechanic), which the correct
`({ page, browser })` form already satisfies. so the runtime is right and the brief is
wrong on both counts.

### a second, smaller defect found in the same pass

`--play` silently accepts only an **absolute** path. a relative path is looked up against
the **skill's own dist dir**, not the caller's cwd:

```
./​.route/…/read-sources.play.ts
  → looked up at node_modules/…/playwright/skills/.route/…  ✗
```

the brief's `.invoke from skill` example shows `--play ./playbooks/login.play.ts`, which
cannot work from any caller outside that dir. either the brief must state the absolute-path
demand, or `browser.action` should look `--play` up against cwd (the better fix —
`rule.prefer.prevent-over-correct`).

## .the shape of the fix

in `rhachet-roles-bhrowser`:

1. rewrite every example in `howto.browser-action-playbooks.md` to

## .why it is not done in this round

- **clean?** ⛔ **no.** the file here is a *booted copy* under `.agent/repo=bhrowser/`,
  synced from `node_modules/rhachet-roles-bhrowser`. an edit here is clobbered on the next
  `rhachet roles boot`, and `pretooluse.forbid-cross-repo-access` guards the upstream. the
  fix must land in the owning repo.

⇒ a tree adopts only what is scoped to itself
(`rule.always.scope-onetime-lessons-to-the-behavior`). re-seeded, never adopted here.
