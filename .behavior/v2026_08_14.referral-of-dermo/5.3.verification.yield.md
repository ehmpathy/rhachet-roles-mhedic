`the current branch <BRANCH> not be read`. tightened to `/branch \S+ <-> route/g` in all three test
files (the sole real branch name is the success footer `branch <name> <-> route`), re-snapped, and

**buttonup fix (peer-convergence pass):** the peer ladder raised two blockers on the bind coverage:
(a) **ANSI escape bytes** leaked into the footer snapshots (`ergo-snapshot-visual-blemishes`), and
(b) the happy-path bind was a **blind stub** (`rhx` → `exit 0`) that could hide a broken bind call
(`mech-given-when-then` / `mech-test-scope-purity`). both are now resolved:

- **(a) ANSI** — the sanitizer strips the raw `\u001b[..m` control bytes (the dim footer render is
  presentation, not content); the biome `noControlCharactersInRegex` rule is satisfied with a
  scoped `biome-ignore` that states the reason. snapshots read clean; lint green.
- **(b) bind stub** — investigated whether a REAL `rhx route.bind.set` could run through the skill
  hermetically. it **cannot**, and the proof is now on record: rhachet resolves its linked-role
  registry ONLY from the exact project root (a temp repo or subdir throws `no skill "route.bind.set"
  found in any linked role`); from the project root the current branch already holds the
  behavior-route bind flag (a conflict); and `setRouteBind` rejects `main`/`master` outright (so CI
  on main could never bind). so a hermetic real-bind-through-the-skill is impossible in any
  environment. rather than a blind stub, the stub now **records the exact args** it was invoked with,
  and each bind case asserts the skill's precise call contract (`route.bind.set --route <ROUTE_PATH>`)
  — the very defect a blind pass-through would hide — while REAL git names the branch for the footer.
  every such stub holds an inline `rule.forbid.integration.mocks` exception with this rationale.
