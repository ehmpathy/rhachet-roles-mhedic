## reshape — supersedes the 21-stone melanoma route (wisher directive, 2026-08-14)

the wisher judged the 21-stone `diagnose.melanoma` route a near-clone of the general open-differential
engine (`diagnose.health`), and thus "convoluted" for so narrow a domain. the directive: distill the
route based on cited inventoried research; amortize the study at build time so the runtime route
**applies** a compiled decision procedure rather than **re-discovers** one per case. this is now codified
as `rule.require.amortize-known-domain-research.[rule].md` (diagnostician role).

### the principle (why the route shrinks)

melanoma is a **closed** domain: a textbook pigmented-lesion differential + validated instruments
(ABCDE, dermoscopy checklists) + published thresholds. per the amortize rule, a closed domain does not
need per-case enumeration/disentangle ceremony — the differential is a known constant. so the route
collapses from an enumeration engine to a **compiled decision procedure**.

### target shape — compiled ~5-stone route (replaces the 21)

1. **intake** — capture lesion history + the ABCDE-relevant observations + red-flag symptoms
   (blood, ulceration, rapid change), PII-redacted
2. **score** — apply the **fixed** ABCDE instrument + a validated dermoscopy checklist against
   **pre-cited** thresholds (from the accrued inventory) — no re-enumeration of the differential
3. **redteam / can't-miss** — the asymmetric-miss guard: amelanotic melanoma, nodular subtype, the
   lesion that changes; the closed set of "must-not-miss" presentations
4. **acuity.binary** — emergency-now (bloody/ulcerated/fast-change) vs. see-a-clinician-soon; the
   binary collapse the vision already mandated (no self-managed "watch" for a melanoma-flagged lesion)
5. **output** — two-layer: plain-language patient summary on top, cited clinical detail beneath

### what feeds which stone (from accrued inventory)

- stone 2 (score) ← ABCDE sens/spec + dermoscopy checklist thresholds
- stone 3 (redteam) ← documented failure modes / can't-miss subtypes
- stone 4/5 ← teledermatology concordance + phone/AI classifier accuracy + FDA status (informs the
  venue/urgency frame and the honest "phone = change-detector, not classifier" copy)

### research-derived structural refinements (fold into the template collapse) — FINAL

- **score stone** frames ABCDE as **spot-evaluation, not a screen**; applies a validated dermoscopy checklist
  (ABCD >4.75 → 0.81/0.72, or 7PCL ≥3 → 0.80/0.67) only where a dermoscopic image exists — a phone photo yields
  ABCDE, whose image-based sensitivity is weak (53%). no single algorithm is superior, so the stone applies a
  checklist, not a mandated one. (cite `melanoma-abcde`, `dermoscopy-algorithms`)
- **redteam stone** — the can't-miss set is now cited-complete: the **outlier ("ugly duckling")** sign;
  **amelanotic/hypomelanotic** melanoma (hardest miss, NNE 27.3); **nodular** subtype; **acral lentiginous**
  (palms/soles/nails — hidden sites); **melanoma from normal skin** (>50% — do NOT assume "no prior mole = benign").
  the rule is "confidently benign vs excise" — absence of a worrisome feature is not benignity.
  (cite `pigmented-lesion-differential`, `melanoma-biopsy-thresholds`)
- **acuity / output** — honest "phone/AI classifier is a change-detector, not a diagnosis" (7% floor sensitivity);
  virtual triage is reasonable and over-refers on the safe side, but melanoma-specific teledermatology accuracy is
  variable — so a virtual read that says "benign" does not close the case. (cite `melanoma-ai-classifiers`,
  `teledermatology-concordance`)
