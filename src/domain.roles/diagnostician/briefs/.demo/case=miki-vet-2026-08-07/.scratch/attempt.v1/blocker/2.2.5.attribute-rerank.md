## what blocks me

the stone's guard runs two peer reviewers at level 1:

- **r1** (`$rhachet.1` → `bhrain review --brain claude/code/haiku`) — **approved**: 0 blockers,
  1 nitpick.
- **r2** (`$rhachet.2`) — **malfunction 💥**, exit 1:
  > `BadRequestError: no skill "enroll" found with --repo bhrain`

the judge `reviewed? --allow-blockers 0 --allow-nitpicks 3` **finished ✓ allowed**. but the stone
passage = `malfunction`, because r2 cannot run at all. the route offers only two exits:
`--as overruled` (human-only) or "fix the reviewer, then retry."

## root cause (diagnosed)

the guard's **r2 peer line invokes a skill that does not exist**: `$rhachet run --repo bhrain
--skill enroll ...`. bhrain has no `enroll` skill — its reviewer skills are `review`,
`review.by`, `reflect`. so r2 is a **malformed reviewer invocation authored into the guard**, not
a verdict on the artifact. it is an author-side tool-level defect, identical in kind to the
`fireworks/deepseek/v4-flash` brain-not-found and `npx rhachet` defects already repaired in the
adjacent guards this session.
