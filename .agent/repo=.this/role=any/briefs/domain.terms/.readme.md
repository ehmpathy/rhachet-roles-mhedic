# domain.terms

## .what

the glossary of this repo's domain vocabulary. one `choice._.` cluster per **term** — a noun,
verb, or adj that composes a domain object or domain operation declared here.

a term is reused across every declaration that uses it: the noun `diagnostician` serves the
role slug, `ROLE_DIAGNOSTICIAN`, and `getDiagnosticianRole` alike.

## .the shape

each term is a cluster of two-to-N files:

| file | level | holds |
|------|-------|-------|
| `term=<x>._.choice._.md` | say | chosen word, kind, forbidden synonyms, refs, one-line `.what` |
| `term=<x>._.choice.reason.md` | ref (**required**) | etymology, disputes, evidence |
| `term=<x>._.choice.example=<abc>.md` | ref (optional) | one per notable example |

see `.agent/repo=bhrain/role=learner/briefs/template.domain-term.md` for the full template.

## .the rules that rule this dir

- `rule.require.domain-term-itemization` — every declared term gets a cluster here
- `rule.forbid.domain-term-synonyms` — contracts use the canonical word, or open a dispute
- `rule.forbid.domain-term-ambiguity` — one word, one sense
- `rule.forbid.domain-term-inconsistency` — one concept, one word
- `howto.domain-term-disputes.[guide].md` — how to argue a term rather than drift from it

## .what does NOT belong here

- generic english that is not domain vocabulary (`file`, `run`, `data`)
- vocab imported from a dependency — `Role`, `RoleRegistry`, `DomainEntity` are rhachet's and
  domain-objects' terms, not this domain's
- a local variable that names no domain concept

| `accrue` | verb | lift a generic cited fact out of a case yield into a reusable, promotable home so research compounds across cases |
